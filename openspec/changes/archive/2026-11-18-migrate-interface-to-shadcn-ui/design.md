# Design

## Context

См. мотивацию в `proposal.md`. Проект использует Next.js 16.4.6, React 19.3.1 и App Router; Tailwind и shadcn/ui отсутствуют. Alias `@/*` уже указывает на `src/*`. Компоненты используют глобальные классы `.button`, `.card`, `.stack-form`, а `globals.css` содержит общие селекторы HTML-элементов.

Собственный `src/components/ui/dialog.tsx` экспортирует `Dialog` и `useDialog` с `close/setBusy`; библиотека источников зависит от этого контракта. Тема задаётся через `data-theme` и cookie `engxam-theme`, а без cookie следует системной через `light-dark()`. `workspace.tsx` собирает команды из FormData; фильтры используют `next/form`, назначения передаются в URL.

Требования к кабинету, теме и типографике действуют в основных спецификациях `study-workspace`, `interface-theme` и `interface-typography`. Manrope уже подключён. `DESIGN.md` отстаёт от текущего интерфейса по палитре и расположению навигации. При миграции сохраняются бордовый акцент и верхняя навигация.

## Goals / Non-Goals

**Goals:** локальная библиотека shadcn/ui без второго параллельного набора контролов; полное покрытие существующих экранов; сохранение server/client границ и контрактов форм.

**Non-Goals:** новые функции, изменение серверных прав, перенос данных, новый бренд, замена верхней навигации боковой панелью, установка всех компонентов каталога. Обычные текстовые ссылки, семантические контейнеры, скрытые поля и системный выбор файлов остаются корректным HTML внутри единой системы оформления.

## Decisions

### 1. Установка в существующий проект

Инициализировать shadcn в существующем npm-проекте через `npx shadcn@<версия> init --base radix`. Выбрать совместимый с Radix пресет и записать его вместе с точной версией CLI в README. Подключить Tailwind CSS 4 и `@tailwindcss/postcss` в `postcss.config.mjs`. В `components.json` задать `rsc: true`, `tsx: true`, `tailwind.cssVariables: true`, `tailwind.config: ""`, `tailwind.css: "src/app/globals.css"`, `aliases.ui: "@/components/ui"` и `aliases.utils: "@/lib/utils"`. Хранить исходники компонентов и `package-lock.json` в репозитории. После переноса прежней обёртки диалога просмотреть план добавления компонентов через `shadcn add --dry-run` или `shadcn add --diff`.

Альтернатива — вручную стилизовать прежние контролы — не выполняет запрос на shadcn/ui. Установка всего registry увеличивает поддержку без пользы. Сверяться с локальной документацией Next перед изменениями: `node_modules/next/dist/docs/01-app/01-getting-started/11-css.md` уже описывает Tailwind/PostCSS для установленной версии.

### 2. Граница общей библиотеки и карта миграции

Использовать Button, Input, Label/Field, Textarea, Native Select, Checkbox, Collapsible, Dialog, Alert, Empty, Badge, Progress, Pagination, Separator по фактическому использованию. Native Select сохраняет поведение FormData и мобильный выбор; собственный выпадающий Select для обычных форм не нужен. Даты и файлы — Input соответствующего типа. Для Checkbox явно сохранить `name`, значение `on`, checked/defaultChecked и участие в FormData.

| Область | Существующие файлы | Применение |
| --- | --- | --- |
| Гостевые формы | login-form, password-form, `(guest)` | Поля, подписи, кнопки, сообщения; сохранить autocomplete и ограничения OTP/пароля |
| Каркас | site-shell, theme, sign-out, study-navigation | Общие варианты кнопок и ссылок, текущий маршрут и выбор назначения; семантика nav сохраняется |
| Главная и показатели | app/page, study-progress | Progress, статусы и пустые состояния; фактические bigint-значения остаются в подписях |
| Источники | library | Диалог создания, редактирование, история, PDF, поиск, архив, пагинация |
| Словарь | glossary | Одиночное и пакетное добавление, предварительный просмотр, привязка источников, редактирование, архив и фильтры |
| Профиль и администрирование | workspace, account | Все ролевые ветки, пользователи, потоки, группы, назначения, тема исследования и руководитель |
| Системные экраны | access-denied, error, not-found, ui/states, ui-preview | Общие состояния и доступные действия восстановления; preview всех используемых примитивов |

Раскрывающиеся редакторы остаются inline на Collapsible; навигационные якоря не превращаются в Tabs, поскольку это изменило бы поведение ссылок. Списки записей остаются непрерывными. Альтернатива в виде готового dashboard block внесла бы лишнюю структуру.

### 3. Диалог без коллизии экспортов

Перед генерацией `ui/dialog.tsx` перенести доменный API в отдельную обёртку, например `source-dialog.tsx`, и обновить импорты library и ui-preview. Обёртка сохраняет `close/setBusy` и управляет `open/onOpenChange`. Для названия диалога использовать `DialogTitle`, для возврата фокуса — `DialogTrigger asChild` или явное восстановление фокуса при закрытии. Скрыть стандартную кнопку через `showCloseButton={false}` и добавить кнопку с доступным именем «Закрыть». Во время операции блокировать кнопку, Escape и взаимодействие вне диалога, сохраняя доступ к явной отмене загрузки PDF. После успешного сохранения закрывать диалог, а после ошибки сохранять введённые значения. Ограничить высоту `DialogContent` и обеспечить внутреннюю прокрутку на мобильных экранах.

Альтернатива — поверхностная замена тега dialog — потеряла бы защиту от закрытия во время загрузки.

### 4. Токены, тема и CSS

Сопоставить текущие цвета семантическим background/foreground, card, muted, border, input, ring, primary, destructive и их foreground-токенам. Не переносить имя старого `--muted` буквально: сейчас оно означает цвет текста, в shadcn — фон. На переходе допустимы однозначные alias, но не две разные семантики одной переменной.

Связать семантические переменные с цветами Tailwind через `@theme inline`. Сохранить cookie `engxam-theme`, атрибут `data-theme` на `html` и существующую логику `color-scheme`. Настроить `dark`-вариант Tailwind для явной тёмной темы и для `prefers-color-scheme: dark` при отсутствии `data-theme`. Явная светлая тема имеет приоритет над системной тёмной и наоборот. Настройка на корне документа распространяется на порталы в `body`. Общий токен шрифта сохраняет Manrope и резервные шрифты.

Проверить порядок слоёв CSS: старые unlayered-селекторы могут перекрыть Tailwind utilities и Preflight. Удалять глобальные правила контролов и дубли состояний по мере миграции; оставить общую типографику, layout и продуктовые композиции в предсказуемых слоях. По завершении убрать устаревшие классы без потребителей и привести DESIGN.md к фактическим токенам и верхней навигации.

### 5. Проверка результата

Использовать текущие unit и Playwright suites, включая foundation, password, neon-auth, session-refresh, education, library и glossary. Дополнить проверки там, где меняется семантика: FormData флажков, busy-диалог, focus return, обе темы в портале и раскрытие редакторов. Сохранить тесты по доступным ролям и именам; обновлять DOM-зависимые ожидания только вместе с эквивалентной проверкой поведения.

Визуально проверить гостевые и авторизованные экраны всех ролей в двух темах на 360, 390, 768, 1280 и 1440 px, с длинными значениями, пустыми списками, ошибками и 200% текста. Для интеграционных проверок использовать предусмотренные проектом тестовые аккаунты и окружение; отсутствие доступа явно отражать в отчёте, не заменяя успешным lint.

## Risks / Trade-offs

- [Preflight и прежний CSS меняют геометрию] → мигрировать слоями, проверять экраны после каждого блока и удалить конкурирующие правила до завершения.
- [Генератор перезапишет существующий dialog.tsx или тему] → сначала перенести адаптер, просматривать diff generated-файлов и не разрешать безусловную перезапись.
- [Интерактивные примитивы увеличат client bundle] → client boundary только в интерактивных листьях; страницы, чтение cookie и серверные данные оставить серверными.
- [Смена контролов меняет FormData и disabled] → Native Select, явное сохранение checkbox value и поведенческие проверки реальных операций.
- [Пресет может заменить шрифт, палитру или настройки темы] → проверить изменения, внесённые CLI, и сохранить существующие настройки Engxam.

## Migration Plan

1. Подготовить конфигурацию, токены, локальные компоненты и адаптер диалога.
2. Перевести каркас и гостевые формы, затем показатели, источники, словарь и все ветки workspace.
3. Закончить системные экраны и preview, удалить устаревшие контролы и синхронизировать документацию.
4. Пройти статические, поведенческие и визуальные проверки до выпуска всей миграции. Промежуточный гибрид не считается завершённым результатом.
5. При откате вернуть только изменения этой миграции, включая зависимости и lockfile; миграции БД и данных не требуются.
