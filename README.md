# Engxam

Подготовка аспирантов к кандидатскому экзамену. Реализация ведётся по [этапам](docs/stages/README.md).

## Запуск

Node.js 22+, рекомендуется 24. `npm ci`, затем `npm run dev:https`. Открыть https://localhost:3000. Для локального сертификата браузер покажет предупреждение; сертификат создаётся только в игнорируемой папке certificates, системное доверие не меняется. HTTPS необходим для корректной проверки secure cookie в Safari.

`neon deploy` применяет neon.ts к привязанному проекту и сохраняет секреты в игнорируемый .env. Дополнительно нужен NEON_AUTH_COOKIE_SECRET (случайное значение минимум 32 символа). Имена настроек перечислены в .env.example. Не коммитить .env, сертификаты или .neon.

## Компоненты интерфейса

Engxam использует Tailwind CSS 4 и локальные исходники shadcn/ui на Radix. Конфигурация создана с помощью shadcn CLI 4.23.0 и пресета Nova (`radix-nova` в `components.json`). Manrope и выбор темы задаются приложением.

Перед добавлением компонента выполните предварительный просмотр, например `npx shadcn@4.23.0 add button --dry-run`. После проверки запустите команду без `--dry-run` и включите исходники и обновлённый `package-lock.json` в изменения.

## Проверки

- `npm run build`, `npm run typecheck`, `npm run lint`, `npm test`.
- `npx playwright install chromium webkit`, затем `npm run test:e2e`.
- `npm run test:db` — временная таблица в транзакции с откатом; проверяет btree_gist, пересечения и блокировку.
- `npm run test:storage` — отдельный временный объект, подписанные PUT/GET, Range, CORS, приватность и запрет перезаписи; объект удаляется в finally.

Удалённый Auth E2E запускается только с RUN_NEON_E2E=1 на тестовой ветке с разрешённой регистрацией. Создаёт временный аккаунт и удаляет его через авторизованный Neon CLI. Обычный CI этот тест пропускает. Не включать публичную регистрацию production ради повторного теста.

## Состояние

Работают адаптивный каркас, вход/выход, установка пароля по email OTP, роли и управление пользователями, потоками, группами и назначениями. Гость с `/` переходит на `/login`. После входа `/` открывает главную со сводкой, а `/account` остаётся разделом профиля или управления в зависимости от роли. Материалы и зачёты относятся к следующим этапам. Managed Neon Auth хранит системные таблицы авторизации; приложение не запускает отдельный Better Auth сервер. Для Vercel Fluid используется pg с attachDatabasePool и Drizzle; миграции используют DATABASE_URL_UNPOOLED.

## Первый администратор

В production создан зафиксированный заказчиком аккаунт zaiden4751@mail.ru с ролью admin в Auth и приложении. На /password пользователь сам запрашивает код и задаёт пароль; секреты не передаются администратором приложения. Доставка в реальный почтовый ящик требует пользовательской проверки; неизвестный адрес получает нейтральный ответ, неверный OTP отклоняется.

Для новой независимой среды: создать Auth-аккаунт через `neon neon-auth user create`, назначить ему `admin` через `neon neon-auth user set-role`, применить `npm run db:migrate`, затем `npm run admin:bootstrap -- EMAIL`. Скрипт отказывается создавать второго администратора и проверяет существующую роль Auth. Дальнейшее управление выполняется в кабинете. Для нескольких экземпляров приложения NEON_AUTH_COOKIE_SECRET должен совпадать.

## Изолированные проверки этапа 02

Для ручной работы с уже созданными тестовыми данными остановить текущий сервер (Ctrl+C) и выполнить `npm run dev:test`. Открыть https://localhost:3000. Команда явно подставляет PostgreSQL, Auth и Storage из .env.stage02, проверяет имя тестовой ветки и не изменяет production-файл .env. Тестовые логины и пароли трёх ролей находятся в локальном игнорируемом файле .env.stage02-fixtures.json. Для возврата к рабочим данным остановить сервер и запустить `npm run dev:https`.

Использована ветка engxam-stage02 с автоматическим удалением 20 ноября 2026. Её настройки находятся в игнорируемом .env.stage02. `ENGXAM_ENV_FILE=.env.stage02` выбирает её для миграций и scripts/test-education.ts; production-файл .env не меняется. Браузерный набор education запускается с E2E_STAGE02=1 и игнорируемыми временными учётными данными .env.stage02-fixtures.json. Перед ним остановить локальный сервер: тест сам запускает сервер на тестовой ветке. Обычный CI пропускает удалённые проверки, требующие fixtures.

Скрипт seed-education-e2e.ts создаёт тестовые аккаунты только при NEON_BRANCH=engxam-stage02 и разрешённой регистрации на этой ветке; после подготовки регистрация закрывается. Не включать её в production. Интеграционный scripts/test-education.ts удаляет только собственные записи с уникальным префиксом.

## Библиотека (этап 03)

Студент и назначенный преподаватель открывают «Источники» (`/library`) и «Словарь» (`/glossary`) из меню кабинета. Выбор учебного назначения сохраняется при переходах. Студент добавляет источник в диалоге на странице списка. Поддерживаются PDF, ревизии, архив, поиск и скачивание; доступ администратора к содержимому закрыт. Объём библиотеки — заявленный, зачёт будет реализован на этапе защит.

`npm run test:literature` проверяет реальные БД/хранилище исключительно ветки engxam-stage02, удаляет собственные тестовые строки и объекты. Браузерный тест library запускается с E2E_STAGE02=1. Не запускать одновременно production dev-сервер и тестовый сервер этого проекта.

Для размещения добавить CRON_SECRET в окружение Vercel; локальное значение остаётся в .env и не переносится автоматически. Расписание vercel.json запускает защищённую очистку ежедневно. Исторические и архивные PDF не удаляются.

## Словарь (этап 04)

Из карточки обучения открыть «Словарь терминов». Студент добавляет отдельные термины или вставляет список, преподаватель читает словарь назначенного студента. Перевод вставляется через TAB; без перевода получается черновик. Сначала выполняется предпросмотр, затем сохранение выбранных строк. Архивный дубль восстанавливается из архива.

`npm run test:glossary` проверяет атомарность, конкурентные запросы и 500 строк исключительно на ветке engxam-stage02, затем удаляет свои записи. Браузерный тест glossary запускается с E2E_STAGE02=1. Принятие преподавателем не начисляется при внесении слова.
