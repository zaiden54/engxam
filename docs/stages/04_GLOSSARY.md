# Этап 04. Словарь и массовый ввод

Зависимость: 03. Результат: студент может быстро внести словарь и подготовить новые термины для обсуждения.

## Задачи

- [x] Создать GlossaryTerm, GlossaryTermRevision, TermSource, ограничения нормализованной уникальности и владения источником.
- [x] Реализовать создание/правку/архив/восстановление, поиск и фильтрацию словаря.
- [x] Реализовать нормализацию NFKC/регистр/пробелы без стемминга, переводов и объединения синонимов.
- [x] Создать textarea: одна строка — термин, опционально TAB и перевод; слова без перевода сохраняются черновиками.
- [x] Создать предпросмотр с номерами строк, дублями, ошибками, счётчиками и редактированием; лимит 500 строк/100 КБ.
- [x] Реализовать атомарный commitBatch с повторной серверной валидацией, защитой от конкурентных дублей и повторов запросов.
- [x] Добавить связь одного термина с несколькими работами без увеличения счётчика терминов.
- [x] Создать адаптивный список: на телефоне слово/перевод сразу, остальные поля по раскрытию; textarea и действия доступны с экранной клавиатурой.

## Проверки и приёмка

- [x] Разный регистр и лишние пробелы не добавляют повторный термин; словосочетание считается одной единицей.
- [x] Массовый ввод не перезаписывает существующие ревизии; конфликт не оставляет скрытую частичную запись.
- [x] Повторное добавление архивного слова предлагает восстановление.
- [x] Импорт 500 строк удобен на ПК и телефоне; ошибки показывают конкретные строки.
- [x] Счётчик внесённых терминов не выдаётся за счётчик принятых.

Пакетную проверку преподавателем реализует этап 06, без добавления временного автоматического принятия слов.


Статус: реализован. Проверены реальные PostgreSQL-транзакции, пакет 500 строк, Chromium и мобильный WebKit. Миграция применена к production; подробности — в [отчёте](04_REPORT.md).
