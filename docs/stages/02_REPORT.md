# Этап 02 — пользователи, доступ и обучение

Созданы миграция и схема восьми таблиц: app_user, student_profile, teacher_profile, academic_period, academic_group, enrollment, audit_event, idempotency_request. Системные таблицы Better Auth принадлежат управляемому Neon Auth, миграциями приложения не меняются.

## Реализовано

- Административный кабинет: создание/подключение аккаунта, ФИО, роли, активация/деактивация, потоки, группы, зачисление и переназначение преподавателя.
- Кабинет преподавателя: только назначенные студенты и их профили. Кабинет студента: своё обучение, правка темы диссертации и руководителя.
- Единый /account с серверной проверкой сессии, актуального active/role и принадлежности данных. Прямая отправка запрещённых полей не обходит права.
- Начальная выдача/восстановление пароля через код Neon Auth на /password. Случайный начальный пароль при административном создании не раскрывается и не отправляется студенту.
- Блокировка изменений, optimistic version, идемпотентность, аудит в транзакции. Уникальность обучения в потоке и составной FK группы/потока.
- Деактивация вызывает ban и revokeUserSessions в Auth; active дополнительно проверяется в БД на каждом серверном запросе. Самоотключение администратора и снятие собственных прав запрещены.
- Создан первый администратор для согласованной почты zaiden4751@mail.ru. Production-регистрация остаётся закрыта.

## Решения и ограничения

- Enrollment хранит period_id как контролируемый ключ для UNIQUE(student_id, period_id). Составной FK к группе исключает расхождение потоков; это уточнение архитектуры.
- Учебные назначения имеют пагинацию по 25. Справочники пользователей/потоков/групп пока ограничены первыми 100; для больших организаций нужны отдельные страницы поиска/пагинации и серверный поиск в селекторах.
- Внешние изменения Auth и транзакция БД не образуют общую транзакцию. При неудаче создания повторная попытка находит существующую Auth-идентичность по точному email и завершает привязку. После сбоя изменения роли/ban операцию можно повторить; права приложения всегда определяет БД, административные endpoints Auth в публичном proxy не открыты.
- Роль пользователя с учебными назначениями менять нельзя, чтобы не разрушать историю. Можно деактивировать аккаунт; перевод преподавателя выполняется отдельным назначением.
- Методы admin в @neon/auth 0.8.2 имеют тип unknown. Контракт изолирован в identity/admin.ts и проверен фактическим E2E, без распространения any по приложению.
- Реальное устройство и рабочий SMTP/доставка писем остаются эксплуатационными проверками пилота. Ранее обнаруженные moderate предупреждения инструментов разработки сохраняются.
