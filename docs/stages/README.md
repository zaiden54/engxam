## Порядок работы

Каждый этап выполняется отдельной задачей: прочитать архитектуру и файл этапа, проверить выполненные зависимости, реализовать только его объём, провести проверки и отметить завершённые пункты. Следующий этап начинается после проверки результата предыдущего. Новые решения обновляются в архитектуре и затронутых этапах; незавершённая задача не помечается выполненной.

## Общие критерии готовности каждого этапа

- [ ] Код проходит typecheck, lint и build; предметные изменения имеют нужные тесты.
- [ ] Миграции воспроизводимы; права проверяются на сервере.
- [ ] Новые экраны проверены на телефоне и ПК, включая loading/empty/error состояния.
- [ ] Нет публичных приватных данных, секретов в клиенте и доверия к вычислениям клиента.
- [ ] Документация соответствует реализации; известные ограничения перечислены в отчёте этапа.

## Зафиксированные правила

Запись не закрывается в среду. Термины принимаются пакетами с исключениями; индивидуальные 500 кликов не требуются. Допуск выдаётся вручную. Адаптивность реализуется с первого этапа. Экзамен, старый Excel-импорт, OCR и экспорт бланка не входят в MVP.

## Решения, которые нельзя незаметно принять за заказчика

Перед этапом 07 отдельно согласовать поведение уже выданного допуска при снижении зачётных показателей. Архитектура предлагает автоматический отзыв, но заказчик подтвердил только ручную выдачу. Прочие задачи этапа могут выполняться независимо. Доступность хранилища проверяется на этапе 01; эксплуатационные параметры восстановления — на этапе 08.
