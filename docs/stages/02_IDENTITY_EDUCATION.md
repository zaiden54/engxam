# Этап 02. Пользователи, права и обучение

Зависимость: 01. Результат: администратор создаёт учебную структуру; пользователи входят и получают только разрешённый доступ.

## Задачи

- [x] Создать миграции предметных User, StudentProfile, TeacherProfile, AcademicPeriod, AcademicGroup, Enrollment; системными таблицами Better Auth управляет Neon Auth.
- [x] Реализовать создание аккаунтов администратором и безопасную первичную установку/восстановление пароля средствами Better Auth; открытую регистрацию выключить.
- [x] Реализовать сессии, logout, деактивацию аккаунта и отзыв сессий.
- [x] Создать централизованные серверные проверки роли и принадлежности Enrollment; не ограничиваться middleware.
- [x] Реализовать управление потоками, группами, назначением преподавателей, зачислением и разрешёнными полями профиля.
- [x] Добавить specialty, language, тему диссертации и руководителя; не дублировать поток в профиле.
- [x] Реализовать AuditEvent и IdempotencyRequest как основу следующих этапов.
- [x] Создать кабинеты трёх ролей с навигацией и честными пустыми состояниями, без фиктивных процентов.
- [x] Документировать начальное создание администратора; исключить публичную выдачу роли admin.

## Проверки и приёмка

- [x] Студент не меняет роль/группу/преподавателя прямым запросом.
- [x] Преподаватель видит только назначенных студентов; после переназначения прежний доступ закрыт.
- [x] Деактивированный пользователь не продолжает работать через старую сессию.
- [x] Дубликаты обучения и несогласованные связи группы/потока блокируются.
- [x] Администратор выполняет управление, а студент редактирует разрешённые поля как на ПК, так и на телефоне.

Изменение целей пока не затрагивает зачёты: правило переоценки реализуется на этапе 07 до появления действующих допусков.


Статус: программная часть реализована и проверена. Заказчик подтвердил доставку OTP на реальную почту. Ограничения справочников и эксплуатации см. в [отчёте](02_REPORT.md).
